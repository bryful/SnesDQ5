# 検証記録

2026-11-19。必要な起動確認と今回修正した16KBアライメントを対象にしています。

## 確認済み

- Windows x64 Releaseビルド成功。
- 手元の対象ROMをSnes9xで600フレーム実行。日本語v1.0、CRC32 BC955F3B、LoROMと認識。256×224の映像と音声サンプルを出力。
- ステートslot1の保存後に実行を進め、復元後のWRAMが保存時と一致。
- 同じ600ゲームフレームの音声サンプル数は1倍速319,829、8倍速40,045。SPC速度制御により約1/8となることを確認。これは音楽・効果音の全場面での正常動作を保証するものではありません。
- Android arm64-v8aのデバッグAPKをビルド成功。接続端末へのインストールとネイティブライブラリの読込を確認。
- 16KB非対応の報告を受け、NDK26から30.0.16248370へ変更。旧APK内のlibmain.soとlibc++_shared.soのLOADアライメントが4,096バイトだったことを確認。
- 修正APK内の両共有ライブラリの全LOADセグメントが16,384バイト。非圧縮.soのAPK内配置も16,384バイト境界であることを確認。
- Android SDKの `zipalign -c -P 16 4` も成功。バージョン0.1.1、versionCode 2。

`build-android.ps1` はAPK作成後に `check-android-alignment.py` を実行し、ELFまたはAPK内配置が16KB未満なら失敗にします。Python3が必要です。

### 実機での自動回転確認

利用者の承認を得て外部の画面回転制御アプリを一時停止。その後、利用者が端末を横に向けた際にSnesDQ5も横向きになることを確認済みです。外部アプリによる縦固定が回転しない原因でした。SnesDQ5側の手動Rotateボタンは削除し、センサーによる自動回転に統一しました。外部の回転制御アプリは確認終了時点で停止状態です。
